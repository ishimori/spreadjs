## 目的

WebSocket upgrade 時に consumer の `authenticate(request)` で接続を検証し、受理後の操作・presence の身元をサーバーが確定する（クライアント申告を信用しない）。

## 決定事項

contract.md §1 ③・§4 5 を採用。追加の実装者判断:

- hook には Node の `IncomingMessage` を渡さず `{ url, headers }` の最小形（Cookie は `headers.cookie`）。
- 拒否は raw socket へ `HTTP/1.1 401` を書いて destroy（hook の throw は 500）。await 中に socket が閉じたら upgrade しない。
- `authenticate` 未指定時は従来挙動（申告値）。診断 `auth-rejected`/`auth-error` は `onDiagnostic` にのみ出す（値は載せない）。
