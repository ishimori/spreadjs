## 目的

**「候補を出しつつ、候補外の値も入力できる」選択式列**を提供する（Excel の入力規則「リスト」でエラー停止を設定しない状態＝実務で最も多い使い方）。

DD-027-1 は「候補のみ（`allowFreeText: false`）」と「実質プレーンテキスト（`allowFreeText: true`）」の 2 状態しか持たず、その中間＝**要件 R1 の本来の姿**が提供されていない。

## 背景・課題

- 要件メモ（松下 `DD-012/sdk-requirements.md`）の **R1 は当初から「選択式入力列。**自由入力と併存**」**（優先度: 高）だった。DD-027-1 は候補のみモードを実装して R1 を成立とみなしたが、consumer の実適用（松下 DD-012-3）で**併存が満たされていない**ことが判明した
- **実測（2026-09-03・松下側セッション）**: `allowFreeText: true` の列はドロップダウン UI が一切出ない。`allowFreeText: false` に変えると候補が正しく出る（consumer 側の配線は正しい）
- 原因は `packages/grid/src/mount-controller.ts` の判定が `isSelectColumn && !allowsFreeText` になっており、**候補 UI の可否と入力検証の厳格さが 1 つのフラグに束ねられている**こと。関係する 3 経路:

| 箇所 | 内容 |
|------|------|
| `mount-controller.ts:1184` | dblclick → `isSelectColumnIndex?.(hit.colIndex)` でドロップダウンを開く |
| `mount-controller.ts:2271` | ▼インジケーター表示の `showIndicator` 条件 |
| `mount-controller.ts:2490` | キー裁定へ渡す `isSelectCell`（Alt+↓ 等） |

いずれも `isSelectCellIndex`（= `registry.isSelectColumn(id) && !registry.allowsFreeText(id)`）を通る。

- consumer 側の制約: 松下は「**マスタに無い値も直接入力できる**」が確定要件（DD-012-1 論点3・ユーザー受付済み）。新しい品番の行をその場で作れないと業務が止まるため、候補のみモードは採用できない。結果として**候補機能を使えないまま**（プレーンテキストで運用・DD-012-3 は「A案: 上流待ち」で受付）
- 対象外: 動的な候補供給（DD-027-1 の拡張点メモ・別要件）／サーバー側の値検証

## 検討内容

| # | 論点 | 選択肢 | 起票時の所見 |
|---|------|--------|------------|
| 1 | API 面 | (a) `allowFreeText: true` でも候補 UI を出す（意味を「検証の厳格さ」だけに限定・**既定挙動の変更**） / (b) `showDropdown?: boolean` 等の別フラグを足す（既定は現行維持） / (c) `mode: 'strict' \| 'suggest' \| 'free'` の 3 値へ整理 | **(a) が要件に忠実**（`allowFreeText` は元々「自由入力の許可」であって「候補を隠す」意味ではない）。ただし既存 consumer が `allowFreeText: true` で「候補を出さない」ことに依存している可能性の確認が要る（0.x・Experimental なので破壊的変更は CHANGELOG 記載で許容される） |
| 2 | 候補外の値の扱い | `allowFreeText: true` のときは従来どおり commit を通す（`validateEditorCommit` は変更しない） | 変更不要の見込み。UI（開く/絞り込む）と検証（通す/弾く）を分離するのが本DDの主旨 |
| 3 | 絞り込み挙動 | 入力中の前方一致で候補を絞る（R1 の要求「IME 入力中の前方一致で絞り込み、Enter/Tab で確定」）。候補が 0 件になったらリストを閉じる（自由入力の邪魔をしない） | 候補のみモードとの差はここ。IME 変換中の絞り込みは実 IME 検証が要る |
| 4 | Enter/Tab の意味 | 候補ハイライト中は候補を確定・ハイライトなしなら入力文字列をそのまま確定 | 「候補を選ばずそのまま打ち切る」が自然にできることが併存の肝 |
| 5 | ▼インジケーター | 自由入力併存列にも出す | 発見性。出さないと候補があること自体に気付けない |
