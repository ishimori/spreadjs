## 目的

ReadyCrew RC5（列見出しのクリック通知）・RC6（セルのホバー通知）を実装する。並べ替え自体・ツールチップ描画自体は consumer 側の責務のまま、SDK は通知と最小限の表示オプションのみを提供する。

## 背景・課題

- RC5 現状: `pointerdown` ハンドラ（`mount-controller.ts:1258-1329`、該当1313-1316）は `hit.area`（`'cell' | 'row-header' | 'column-header' | 'corner'`）を区別せず、`cell` 以外は一律 `editor.pointerdownCell(null)`（選択解除）のみ。列見出しクリックを検知する分岐が無い
- RC6 現状: `pointermove` ハンドラ（1134-1219行目、該当1135-1210）はリサイズドラッグ・選択ドラッグ・カーソル切替のみを扱い、ホバー通知は無い。`GridEvent`（`index.ts`）は `connection`/`pending`/`rejected`/`divergence`/`error`/`layout`/`cell-commit`/`row-structure-change`/`link-open`/`remote-change`/`presence` の10種のみ
- 親 DD-052 決定（論点6）: RC4 (a) は DD-052-4。**RC5 提示のとおり**＝`header-click{columnId}` イベント＋並べ替え中を示す表示オプション（並べ替え自体は consumer）。**RC6 (a)**＝`cell-hover{rowId,columnId,rect}`（出入りで発火・間引きあり。consumer が Markdown/HTML で描ける）

## 検討内容

- RC5 の表示オプション（並べ替え中インジケータ）の具体形（列単位の矢印表示か、テキストか）は Phase 1 で既存のヘッダー描画コード（`packages/render/`）を実読して決める
- RC6 の間引き方式（rAF・時間ベースのdebounce等）は Phase 1 で既存の `pointermove` 内の他の処理（リサイズ）と整合させて決める

## 決定事項

- `GridEvent` に `{ type: 'header-click'; columnId: string }` を追加。`pointerdown` が `hit.area === 'column-header'` を検知したら発火する（既存の選択解除等の挙動は変えない）。行番号ヘッダー・コーナーは対象外
- `GridEvent` に `{ type: 'cell-hover'; rowId: string | null; columnId: string | null; rect: GridCellRect | null }`（`GridCellRect={x,y,width,height}`。セルから離れたら全 null）を追加。`pointermove` で対象セルが変わった時だけ発火する（同一セル内の移動では再発火しない＝間引き）
- **並べ替えインジケータ表示オプション（論点6原案の一部）は本DDの範囲から外す**（実装時の判断・下記「範囲の見直し」参照）。RC5 の核＝クリック通知は当初どおり実装する

## 範囲の見直し（Phase 1・実装時判断）

DD-052 論点6の原案は RC5 に「並べ替え中を示す表示オプション」を含めていたが、これは以下の理由で本DDの範囲から外す:

- RC5 の核心的な不足（優先度「中」の根拠）は「列見出しクリックの通知が無い」ことであり、表示オプションはその上に乗る付加的な UX（ADR-018 の sort/filter を先取りしない、という当初方針にも合致）
- 並べ替え自体は consumer 実装（本DD決定どおり）である以上、並べ替え中の視覚表現（矢印等）も consumer 側で自前描画すれば `header-click` の通知だけで成立する（consumer は自分の並べ替え状態を持っており、SDK に別途状態を渡す必要性が薄い）
- 表示オプションを追加すると `packages/render` のヘッダー描画へ新規の描画分岐が要り、Risk Class・検証範囲が RC6 相当まで拡大する。ReadyCrew の要件メモは「通知が無い」ことを不足点として挙げており、表示オプションを明示要求していない
- 実要望が出た時点で別 DD として起票する（本節の記録を出典にする）
