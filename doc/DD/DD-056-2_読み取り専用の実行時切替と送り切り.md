## 目的

他人の操作で自分のシートが読み取り専用になっても、未送信の操作と編集中の入力を失わないようにする（開き直さずに切り替える）。
自分の操作（提出・締切・確定）の前に、編集中のセルを確定して送り切るまで待てるようにする。
あわせて、Tier 1 で変換確定の直後に別セル・グリッド外をクリックしても確定されない既存の不具合を直す。

## 背景・課題

- 要件は親 DD-056 の H12。HEAD の実読結果は `DD-056/contract.md` §1.3・§1.4
- 変換確定の直後（`EditingAwaitFinalInput`）は Tier 1 の通常の状態で、blur では確定しない（Codex 設計レビュー P1-2・実機トレース DD-035）。既存のクリック・blur の確定漏れも同じ原因（contract.md §4.5）

## 決定事項

- `GridInstance.setReadOnly`・`pendingCount`・`flush`、React の `readOnly` の写像と handle の `pendingCount`・`flush`。契約は `DD-056/contract.md` §4.1〜§4.4
- 編集中のセルの確定は §4.2（状態機械は改変せず、位相ごとに既存のイベントを渡す。変換確定の直後は textarea の値を最終 input の代わりに渡す）
- 既存不具合の修正は §4.5（実際のクリック・blur を `EditingAwaitFinalInput` で受けたら macrotask で判定し、まだ同じ位相なら最終 input の代わりを渡す）
- 内部の変更点は §4.6

## 受け入れ基準

| # | 基準（操作 → 期待結果） | 検証方法 |
|---|------------------------|---------|
| 1 | 編集中に `setReadOnly(true)` → 編集中の値が確定・送信され、開き直さない（instance・scroll・選択を保つ）。以後は入力・貼り付け・Delete・行操作・Undo/Redo・候補欄が効かない。`setReadOnly(false)` で戻る | E2E |
| 2 | 未送信の操作がある状態（オフライン）で `setReadOnly(true)` → 再接続で操作がサーバーへ届く | E2E |
| 3 | 順序B の synthetic composition（compositionend の後に非変換の input を流さない）の直後に `setReadOnly(true)`・`flush()` → 確定値が送られる | E2E・`ime-editing-session` unit |
| 4 | 変換中（compositionend 前）に `setReadOnly(true)` → 変換が終わるまで textarea は触られず、終わった後に値が送られて読み取り専用になる。その間に他の入口（貼り付け・行操作 API）は効かない | E2E |
| 5 | `flush()` → 送り切ると `flushed`。オフラインで上限を過ぎると `timeout`（`pendingCount`・`editing` 付き）。接続終端・destroy で `stopped`。単独モード・boot 前はすぐ `flushed` | E2E・flush 判定関数の unit |
| 6 | **既存不具合の修正**: 順序B の変換確定の直後に別セルをクリック → 元のセルへ確定してクリック先へ移る／グリッド外をクリック → 確定して移動しない。順序A（compositionend → 非変換の input）では従来どおり（二重確定・ゴースト編集なし） | `ime-editing-session` unit（macrotask を進めて検証）・E2E |
| 7 | React の `readOnly` prop を変えても開き直さない（未送信の操作が残る）。他の識別系 props の変更では従来どおり開き直し、新しい mount に現在の `readOnly` が渡る。handle の `pendingCount`・`flush` が直結し、mount 前は `0`・`flushed` | React unit（jsdom）・React E2E |
