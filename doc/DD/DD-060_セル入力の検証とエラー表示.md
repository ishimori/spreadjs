## 目的

業務の入力画面で、**入力値が規則に合わないセルを、そのセルの上で分かるようにする**（赤枠・背景・ツールチップ等）。
必要なら、規則に合わない値の確定そのものを止める。

## 背景・課題

- OFIC の入力画面（部所・HD・グループ会社の業績報告）を `@nanairo-sheet/react` で作る。先方の現行 Excel は申請時に、
  AS400 の項目定義（桁・数値・小数）でセルを検査し、エラーのセルに色を付けて別シート（エラーリスト）に一覧を出している
  （OFIC `doc/analysis/03_input-forms.md` §4.2）
- SDK で確定前に検証できるのは選択式列（`columnTypes` の select）の候補検証だけ。任意の規則で確定を止める口がない
- 確定後に consumer が検証しても、**特定のセル（行×列）に印を付ける手段がない**。`columnFormats` は表示文字列の完全一致、
  `rowBackgrounds` は行全体で、どちらもセル単位のエラー表示に使えない。OFIC は当面、エラー一覧を画面の外に出して申請を止める形で回避する

## 検討内容

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A | 確定前の検証フック `validateCell?: (cell: { rowId; columnId; value }) => string \| null`（同期）。null 以外なら確定しない（編集を続け、メッセージを出す）。貼り付けは1件でも不正なら全体を拒否（現行の全成功/全失敗に合わせる） | Excel の入力規則に近い。不正値が文書に入らない | IME の確定経路・貼り付け・敷き詰め・Undo に触れる（Risk A） |
| B（推奨・先行） | セル単位の状態表示。単独モードの行データに `cellStatus?: Record<columnId, { level: 'error' \| 'warning'; message?: string }>` を足し、枠・背景で描き、ホバーでメッセージ（`cell-hover` に載せる）。consumer が確定後に検証して `setRows` で付け外しする | 描画と行データの追加だけで済む（Risk B）。サーバー側検証の結果も同じ口で出せる | 不正値はいったん確定する（申請時に止めるのは consumer の責務） |

案B を先に出し、確定そのものを止める要求が複数案件で出たら案A を別DDにする、を推奨する。

## 決定事項

2026-10-22 の Human Spec Gate でユーザーが推奨案を選んだ。細目（★）は推奨案の説明に含めて提示した内容と、それに沿って詰めた設計。

1. **案B だけを先に出す**。案A（確定前に止める）は、要求が複数案件で出たら別DDにする
2. **表示は枠＋薄い背景**: error = 赤枠 2px（`#d93025`）＋背景 `#fce8e6`、warning = 橙枠 2px（`#e37400`）＋背景 `#fef7e0`
   - ★ 値の有無によらず付く（空のセルにも付く）。枠はセルの内側（罫線の内側）に描く
   - ★ 背景は列背景・行背景・値の書式（`columnFormats` の `cellBackground`）より優先する。文字・バッジ・枠はその上に描く
   - ★ 色は固定（設定項目を増やさない）。変えたい要求が出たら別途
3. **メッセージは `cell-hover` に載せるだけ**: イベントに `status?: { level; message? }` を足す（状態のないセルでは付けない）。ツールチップは consumer が `rect` を使って出す。SDK に新しい UI は足さない
   - ★ ホバー中のセルの状態が `setRows`／`setData` で変わったら、同じセルのままでも `cell-hover` を出し直す（確定直後に検証して印を付けたとき、マウスを動かさなくてもメッセージが出せるように）
4. **省略は保持、`{}` で消す**（行単位の `readOnlyColumns` と同じ決まり）。`setRows` で `cellStatus` を渡した行は、その行の状態を丸ごと置き換える。省略した行は前の状態を保つ。起票時の受け入れ基準2（省略で消える）はこの決まりへ書き換えた
   - ★ `setData`／`initialData` は文書と一緒に状態も丸ごと作り直す
   - ★ 未知の列は黙って飛ばす（`cells`・`readOnlyColumns` と同じ）。`level` が `error`／`warning` 以外のセルは無視し、診断 `warn`（`cell-status-invalid`）を1回出す
   - ★ 状態は文書のデータではない: 利用者がセルを編集しても状態は消えない（consumer が検証し直して付け外しする）。Undo/Redo・cell-commit・コピー・貼り付けの対象にならない
   - ★ 単独モード専用（共同編集モードでは `setRows`／`setData` 自体が無視される。`readOnlyColumns` と同じ）

## 詳細設計（実装前に固定）

| 層 | ファイル | 変更 |
|---|---|---|
| 公開型 | `packages/grid/src/index.ts` | `GridCellStatus { level: 'error' \| 'warning'; message?: string }` を足し、`GridStandaloneRow.cellStatus?: Readonly<Record<string, GridCellStatus>>` と `cell-hover` の `status?: GridCellStatus` を追加。React からも型を re-export する |
| 行データ | `packages/grid/src/standalone-session.ts` | `cellReadOnly` と同じ形で `cellStatus: Map<rowId, Map<columnId, GridCellStatus>>` を持つ。`buildDocument` で作り直し、`setRows` で行ごとに置き換える。`cellStatusOf(rowId, columnId)`・`hasAnyCellStatus()` を公開する。状態だけの変更でも再描画を要求する（`view.markCellDirty()`。Undo の対象には入れない） |
| 描画 | `packages/render/src/base-layer.ts` | フック `cellStatusesInRow?: (rowIndex) => readonly { colIndex; level }[] \| undefined` を足す。pane ごとに、行背景の後・罫線の前で状態の背景を塗り、値の描画の後で内側の枠を描く。値の書式の背景は状態のあるセルでは塗らない（状態の背景を消さない）。未指定なら追加描画ゼロ |
| 結線 | `packages/grid/src/mount-controller.ts` | 単独モードでフックを束縛し（状態が0件なら即 `undefined`）、行 index→RowId、ColumnId→列 index を毎描画で解決する（行の挿入・削除・並べ替えに追従）。`updateCellHover` で `status` を載せ、`setRows`／`setData` の後にホバー中セルの状態が変わっていれば出し直す |
| 文書 | quick-start・CHANGELOG・`apps/showcase/src/features.json`・`tests/contract` の公開面 snapshot | 使い方（確定後に検証して `setRows` で付け外し）と、ツールチップの出し方の例 |

## 受け入れ基準

| # | 基準（操作 → 期待結果） | 検証方法 |
|---|------------------------|---------|
| 1 | `setRows([{ rowId, cellStatus: { m09: { level: 'error', message: '8桁を超えています' } } }])` で該当セルに赤枠＋薄赤の背景が付く。`warning` は橙枠＋薄黄。空のセルにも付く | 描画テスト |
| 2 | `cellStatus: {}` で `setRows` するとその行の表示が消え、`cellStatus` を省略した `setRows`（`cells` だけの更新）では表示が残る。どちらも行の他のセル値・Undo 履歴は変わらない（状態だけの変更は Undo の対象にならない） | 単体テスト |
| 3 | 状態のあるセルにホバーすると `cell-hover` に `status`（level・message）が載る。状態のないセルでは載らない。ホバー中のセルの状態が変わると出し直す | 単体テスト |
| 4 | cell-commit・コピー TSV の値は変わらない（状態は値に混ざらない） | 既存の契約テスト＋単体テスト |
| 5 | `setData`／`initialData` の `cellStatus` でも同じ表示になり、`setData` で状態が作り直される | 単体テスト |
| 6 | 列背景・行背景・値の書式の背景があるセルでも、状態の背景と枠が見える。固定行・固定列の中でも描かれる | 描画テスト |
| 7 | 未知の列は黙って飛ばし、不正な `level` は無視して診断 `warn` を出す | 単体テスト |
| 8 | React Facade の `setRows`／`initialData` からそのまま使え、`GridCellStatus` を import できる | typecheck・consumer-strict・公開面 snapshot |
