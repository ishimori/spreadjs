## 目的

consumer が指定した範囲のセルを1つのセルとして描き、選択・移動・コピー・貼り付けをその範囲に合わせる（セルの結合）。合わせて、列のまとまりの名前を見出しの上に出す（2段の見出し）をこの DD で扱うかを決める。

## 背景・課題

- consumer（hiroshima-keikaku。広島国際空港の計画策定システムの試作）が、各部の入力シートを単独モードで作る（同リポジトリ DD-001-15）。先方の Excel は明細ごとに「予算・実績＋見通し・差異」の3行で、明細の属性の列（No・事業・部署・科目など）を3行にまたがって結合している。ユーザーが「セルの結合は UI として重要」とし、SDK に足すことを積極的に検討する（2026-11-07）
- 開発計画 §12.7 では、セルの結合は後の段階の予定で、固定 ID の矩形端点で持つ・重なりを禁止する・範囲の中のヒットを左上へ正規化する・可視範囲に交わる結合だけを引ける index を持つ・行列の削除で範囲が壊れたときの縮小／解除の規則を ADR で決める、とされている（ADR-019「セル結合の初期制約」は Open。D-17）。MergeCells／UnmergeCells は後続の Operation
- consumer の要件は**表示のための結合**: 範囲は consumer が自分のデータ（明細ごとの行）から決め、結合したセルは読むだけ（K1〜K3）。開発計画の MergeCells（利用者が画面で結合し、共同編集で共有する文書の状態）より狭い
- 現状（alpha.18）: 結合なし。2段の見出しもなし（DD-033-2 で対象外。拡張点メモに「2段ヘッダー」）。consumer は、属性を明細の最初の行だけに出し、明細の境を `rowBorders` の太線にするつなぎで先に進む
- 時期: consumer の試作は 11/12 にユーザーレビュー、11/13 に先方へ渡す。間に合わなければ結合なしの形で渡し、後で差し替える（試作は SDK を待たない）。consumer の本体（受注後）は 2027年1〜3月の着手の可能性がある

## 検討内容

論点1〜6 は起票時の推奨案、論点7〜12 は開始前の確認（2026-11-07）で見つけた「推奨案のままだと実装で詰まる所」。2026-11-08 にユーザーの指示で、すべて下の推奨案で確定した（決定事項）。公開 API の細目は `DD-064/contract.md` が正本。

| # | 論点 | 推奨案（確定） |
|---|---|---|
| 1 | 範囲（どの結合か） | **表示のための結合（view-local）**。consumer が mount オプション `mergedCells` と命令 `setMergedCells`（論点7）で範囲を渡す。文書の状態・Operation・snapshot・protocol は変えない（`rowBackgrounds`・`rowBorders` と同じ置き場）。両モードで使え、共同編集モードで各クライアントが同じ指定を持つのは consumer の責務。利用者が画面で結合・解除する MergeCells／UnmergeCells は後の段階のまま |
| 2 | 結合したセルの編集 | 読むだけ（K3）。範囲の中は編集開始（印字キー・F2・ダブルクリック・IME）・Delete／Backspace・選択式の候補欄・日付のカレンダーを開かない。貼り付け・範囲の消去・cut は、読み取り専用の行・列と同じく結合範囲のセルを飛ばす。送信直前の保証層（`readOnlyColumns` の chokepoint）には入れない（表示の設定なので、Undo／Redo・`setData`・`setRows`・リモートの変更は通す）。編集できる結合は、要望が出たら別 DD |
| 3 | 選択・移動・コピー | 範囲の中を選ぶ（クリック・`setActiveCell`・移動の結果）と左上のセルを選び、選択の枠は範囲全体に描く。矢印キー・Tab・Enter は範囲を1つのセルとして動く（下・右へは範囲の外へ出る）。範囲の選択（Shift＋矢印・Shift＋クリック・ドラッグ）が結合にかかったら、結合の全体を含むように広げる（Excel と同じ）。コピーは左上に値・残りは空（範囲の中の他のセルに値があっても空） |
| 4 | 指定の誤りと行の入れ直し | **形の誤り**（未知の列・列の範囲が右端を越える・固定列の境界をまたぐ・1×1・行数／列数が1以上の整数でない・同じ左上の重複）は、mount オプションなら fail-fast（error phase=config・code=`merged-cells-invalid`）、`setMergedCells` ならその指定だけ捨てて診断 warn（論点9）。**行に関わる判定**（未知の行・行が足りない・固定行の境界をまたぐ・ほかの結合と重なる）は描画の時に行い、その結合を張らずに診断 warn（重なりは行の並びが分かるまで判定できないため、起票時の「mount 時に fail-fast」から変えた）。行の挿入・削除・入れ直しで、張った範囲の行が欠けたり間に行が入ったりしたら、壊れたとしてその結合を捨てて warn（縮小・拡大の規則は ADR-019 で後に決める） |
| 5 | 2段の見出し（K4） | **この DD に含める**。表示だけの mount オプション `columnGroups: [{ caption, columnIds }]`（mount 時固定）。指定があれば見出しを2段（24px×2）にし、まとめた列は上の段にまとまりの名前・下の段に列の名前、まとめていない列は2段ぶんに列の名前を出す。列は `columnOrder` で隣り合うこと・まとまり同士が重ならないこと・固定列の境界をまたがないこと（mount 時に fail-fast・code=`column-display-invalid`）。上の段のクリックは `header-click` を出さず、上の段のまとまりの中の境界では列幅を変えられない |
| 6 | 描画 | 結合範囲は1つの大きなセルとして描く（背景・文字・状態表示は左上のセルのもの。範囲の中の罫線は、グリッド線も `rowBorders`・`columnBorders`・`defaultRowBorder` も描かない）。文字はふつうのセルと同じ決まり（縦の中央・数値は右寄せ・折り返しの列で2行以上なら上から）で範囲の中に描き、収まらない文字は … で切る（右隣へはみ出さない。左のセルの文字も結合の手前で止まる）。結合範囲の文字で行の高さを自動で伸ばさない（Excel と同じ）。固定 pane とスクロール側にまたがる範囲は張らない（論点4・10）。範囲の上の端が隠れたときの文字は、範囲と一緒に動く（Excel と同じ） |
| 7 | 命令の形 | `setMergedCells(mergedCells)` を両モードに足す（全体を置き換える・`[]` で全部外す・同じ内容なら何もしない）。`setData` には同梱しない（共同編集モードでは `setData` が no-op のため）。結合を張るのは次の描画の時なので、`setData` と `setMergedCells` は同じ処理の中ならどちらを先に呼んでも結果は同じ。boot 前に呼んでもよい。React は `mergedCells` props（値が変わったら開き直さずに `setMergedCells` を呼ぶ。`readOnly` と同じで、handle には出さない） |
| 8 | 未知の行の扱い | 描く時に解決する（`rowBorders`・`setCellStatus` と同じ）。左上の行が無い・下に行が足りない間は張らずに診断 warn を1回出し、行が届いたらその時に張る（共同編集モードで行が後から届く場合も同じ）。見た目は K2 の「捨てて warn」と同じ |
| 9 | 誤りの知らせ方 | mount オプションの形の誤りは fail-fast。`setMergedCells` の形の誤りは throw せず（既存の命令と同じ）、その指定だけ捨てて診断 warn（code=`merged-cells-invalid`）し、残りは張る。描画の時の判定は診断 warn（code は `merged-cell-unresolved`＝行が無い・足りない、`merged-cell-conflict`＝重なり・固定の境界、`merged-cell-broken`＝行の挿入・削除で壊れた。どれも1つの指定につき1回） |
| 10 | 固定行の既定値 | `frozenRowCount` の既定 1（先頭のデータ行が固定）は変えない。固定行の境界をまたぐ範囲は張らずに warn（fail-fast にしない。行の並びで決まるため）。先頭の行から結合するときは `frozenRowCount: 0` にすることを JSDoc・README に書く |
| 11 | 範囲の持ち方 | 指定は左上のセル＋行数・列数（K1）。張る時に、その時の行の並びで範囲に入る行の ID を覚え、以後はその行で持つ（固定 ID・開発計画 §12.7）。範囲の上・下に行が入っても範囲は行と一緒に動く。覚えた行が欠けた・間に行が入った・並びが変わったら壊れたとして捨てる（論点4）。列は固定なので index で持つ |
| 12 | 2段の見出しと DD-042 | まとまりは固定列の境界をまたげない（論点5）ので、DD-042（固定境界で切れた見出しが別字に見える）と同じ現象はまとまりの名前では起きない。列の名前の描き方は今のまま（DD-042 は別に扱う） |

- 2026-11-08: ADR-019（セル結合の初期制約）は **Open のまま残す**。この DD は表示のための結合（view-local）で、文書の結合（MergeCells）の初期制約・D-17（削除規則）は決めない。開発計画の ADR 表と D-17 に、表示のための結合を DD-064 で先に出したことを1行足す

- K5（セル単位の読み取り専用）は consumer が「範囲外でよい」としたため対象外
