## 目的

consumer が並べ替え・絞り込みをしたとき、文書を作り直さずに（`setData` を使わずに）見せる行とその並びだけを変える。一覧のまま編集できる。大きい表（DD-070-1 の計測で `setData` は 100 万セルあたり約 1 秒）でも速い。

## 背景・課題

- 今は並べ替え・絞り込みを `setData` で反映するしかなく、Undo が消え、大きい表では毎回数秒かかる
- 画面の行の並びは `DocumentView` の行の Axis の 1 か所で文書から組み立てている（描画・選択・範囲の操作は番号を ID に引き直す）

## 決定事項

- 2026-11-20（親 DD-070・推奨案で確定）:
  1. 命令 `setRowView(rowIds | null)`: 見せる行を見せる順に渡す（並べ替え＝全部の行を並べ替えて渡す・絞り込み＝残す行だけ渡す）。`null` で文書の並びに戻す（全部見せる）。view-local・両モード（共同編集の確かめは DD-070-9）・開き直さない（Undo・スクロール位置を保つ）。命令 `visibleRowIds()` で今見せている行を見せる順に返す（CSV を「見えているとおり」に作る材料）
  2. 一度きりの並び（Excel と同じ）: 値を変えても並び直さない・絞り込みの条件に合わなくなっても隠さない（consumer が次に `setRowView` を呼ぶまで）
  3. 呼んだ時点にあった行で渡さなかった行は隠す。呼んだ後にできた行（`insertRows`・ショートカット・`setRows` の新しい行）は、文書の並びで一つ前の見えている行のすぐ後に見せる（無ければ先頭）。消した行は並びから抜ける。`setData` で新しい行 ID で入れ直すと、全部「呼んだ後にできた行」になる（＝文書の並びで全部見せる）。同じ行 ID で入れ直したら並びは残る（行 ID で覚えているため・実装で確認して手引きに書いた）
  4. 隠した行（並びに無い行）は範囲の操作（選択・コピー・切り取り・範囲の消去・貼り付け・Ctrl+D）の外（見えている行だけ。Excel の絞り込みの範囲の消去・Ctrl+D と同じ。貼り付けは見えている行へ続けて書く）。値は文書に残り、`getRows` では読める。Undo は隠した行の値も戻す（画面には出ない）
  5. 選択中のセル・範囲は行 ID を追って新しい並びへ（既存の再ベース）。選択中の行を隠したら、前の並びで下の一番近い見えている行へ（無ければ上）
  6. 編集中に呼んだら、編集中のセルを確定してから並びを変える（移動はしない）。IME の変換中なら、変換が終わってから確定して変える（`setReadOnly` と同じ）
  7. 固定行は見せる並びの先頭の n 行。行をまたぐ結合は並びが変わると張れなくなる（既存の決まりで捨てる・診断 warn）。並べ替え・絞り込みと行をまたぐ結合は一緒に使わない（手引きに書く）
  8. `scrollToRow`・`setActiveCell` で隠した行を指したら何もしない（診断 info `row-hidden`。未知の行の warn と分ける）。行の初回の未知の検査（`readOnlyRows`・`rowBackgrounds`・`rowBorders`）は文書にあるかで判定する（隠れているだけなら warn しない）
  9. 不正な値（配列でも null でもない・文字列でない ID）は何も変えずに診断 warn（`row-view-invalid`）。未知の行 ID は無視（warn）。重複は最初の 1 つ
  10. 5 万行でも `setRowView` は O(行数)（並びの組み立てと Axis の作り直し）。並びだけが変わったときは自動の行高を測り直さない
