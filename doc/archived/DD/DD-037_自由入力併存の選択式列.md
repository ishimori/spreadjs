## 目的

**「候補を出しつつ、候補外の値も入力できる」選択式列**を提供する（Excel の入力規則「リスト」でエラー停止を設定しない状態＝実務で最も多い使い方）。

DD-027-1 は「候補のみ（`allowFreeText: false`）」と「実質プレーンテキスト（`allowFreeText: true`）」の 2 状態しか持たず、その中間＝**要件 R1 の本来の姿**が提供されていない。

## 背景・課題

- 要件メモ（松下 `DD-012/sdk-requirements.md`）の **R1 は当初から「選択式入力列。**自由入力と併存**」**（優先度: 高）だった。DD-027-1 は候補のみモードを実装して R1 を成立とみなしたが、consumer の実適用（松下 DD-012-3）で**併存が満たされていない**ことが判明した
- **実測（2026-09-03・松下側セッション）**: `allowFreeText: true` の列はドロップダウン UI が一切出ない。`allowFreeText: false` に変えると候補が正しく出る（consumer 側の配線は正しい）
- 原因は `packages/grid/src/mount-controller.ts` の判定が `isSelectColumn && !allowsFreeText` になっており、**候補 UI の可否と入力検証の厳格さが 1 つのフラグに束ねられている**こと。関係する 3 経路:

| 箇所 | 内容 |
|------|------|
| `mount-controller.ts:1184` | dblclick → `isSelectColumnIndex?.(hit.colIndex)` でドロップダウンを開く |
| `mount-controller.ts:2271` | ▼インジケーター表示の `showIndicator` 条件 |
| `mount-controller.ts:2490` | キー裁定へ渡す `isSelectCell`（Alt+↓ 等） |

いずれも `isSelectCellIndex`（= `registry.isSelectColumn(id) && !registry.allowsFreeText(id)`）を通る。

- consumer 側の制約: 松下は「**マスタに無い値も直接入力できる**」が確定要件（DD-012-1 論点3・ユーザー受付済み）。新しい品番の行をその場で作れないと業務が止まるため、候補のみモードは採用できない。結果として**候補機能を使えないまま**（プレーンテキストで運用・DD-012-3 は「A案: 上流待ち」で受付）
- 対象外: 動的な候補供給（DD-027-1 の拡張点メモ・別要件）／サーバー側の値検証

## 検討内容

| # | 論点 | 選択肢 | 起票時の所見 |
|---|------|--------|------------|
| 1 | API 面 | (a) `allowFreeText: true` でも候補 UI を出す（意味を「検証の厳格さ」だけに限定・**既定挙動の変更**） / (b) `showDropdown?: boolean` 等の別フラグを足す（既定は現行維持） / (c) `mode: 'strict' \| 'suggest' \| 'free'` の 3 値へ整理 | **(a) が要件に忠実**（`allowFreeText` は元々「自由入力の許可」であって「候補を隠す」意味ではない）。ただし既存 consumer が `allowFreeText: true` で「候補を出さない」ことに依存している可能性の確認が要る（0.x・Experimental なので破壊的変更は CHANGELOG 記載で許容される） |
| 2 | 候補外の値の扱い | `allowFreeText: true` のときは従来どおり commit を通す（`validateEditorCommit` は変更しない） | 変更不要の見込み。UI（開く/絞り込む）と検証（通す/弾く）を分離するのが本DDの主旨 |
| 3 | 絞り込み挙動 | 入力中の前方一致で候補を絞る（R1 の要求「IME 入力中の前方一致で絞り込み、Enter/Tab で確定」）。候補が 0 件になったらリストを閉じる（自由入力の邪魔をしない） | 候補のみモードとの差はここ。IME 変換中の絞り込みは実 IME 検証が要る |

| 5 | ▼インジケーター | 自由入力併存列にも出す | 発見性。出さないと候補があること自体に気付けない |

## 決定事項

Human Spec Gate 確定（2026-09-03・ユーザー承認）:

| # | 論点 | 決定 |
|---|------|------|
| 1 | API 面 | **(a) 採用**。`allowFreeText` の意味を「候補外値の commit 可否（検証の厳格さ）」だけに限定し、`true` でも候補 UI を出す（既定挙動の変更）。公開 `.d.ts` は候補 UI の表示可否を約束していないため契約違反ではない。0.x Experimental につき CHANGELOG に破壊的変更として明記する |
| 2 | 候補外の値の扱い | `allowFreeText: true` は従来どおり commit を通す。`validateEditorCommit` は無改変 |
| 3 | 絞り込み挙動 | 入力中の前方一致で候補を絞る。候補 0 件でリストを閉じ、自由入力を継続できる |
| 4 | Enter/Tab の意味 | 候補ハイライト中は候補を確定。ハイライトなしなら入力文字列をそのまま確定（候補外でも通る） |
| 5 | ▼インジケーター | 自由入力併存列にも表示する（発見性を優先） |

**影響確認（Phase 1 調査結果）**: `apps/showcase/src/demo/main.ts`（col-3）は表示面のみ変化（コード変更不要）。`apps/playground/e2e/column-types-select.spec.ts` **AC5** はコメント・前提（「allowFreeText:true＝isSelectCell 対象外」）の更新が必要（Phase 2 タスクへ追加済み）。既存 unit テスト（`column-types.test.ts`）は `allowsFreeText` / `validateEditorCommit` の意味を変えないため無修正で green の見込み。

**実装時の設計確定（Phase 2・決定④の具体化）**: 候補 UI を 2 モードに分けた。

| モード | いつ出るか | キーの所有権 | 候補の選び方 |
|---|---|---|---|
| **picker**（従来） | Navigation で明示操作（dblclick / F2 / Enter / Alt+↓） | ↑↓/Enter/Esc/Tab を奪う（DD-027-1 と同一） | ↑↓ でハイライト → Enter |
| **suggest**（新規） | 自由入力併存列の**編集中**に draft の前方一致で自動表示 | **一切奪わない**（`decideSelectKey` は非 Navigation で必ず 'none'） | クリック。ハイライトは付かない＝Enter は入力文字列を確定 |

編集中に ↑↓ を候補移動へ割り当てることは**見送った**: 状態機械は編集中の矢印を「キャレット移動」と定義しており（`editor-state-machine.ts`）、奪うと折り返し列の複数行キャレット移動を壊す。かつ Risk 欄の「editor-state-machine・IME は無改変」に抵触する。キーボードだけで候補を選びたい場合は Alt+↓ で picker を開く経路が使える（AC3 は picker で成立）。→ 既知の未保証境界へ 1 行移送。

- ~~**実 MS-IME での変換中の候補絞り込みは未確認（Manual Gate T1 未実施）**~~ → **2026-09-04 に後追い実施し解消**（`ime-manual-gate-ledger.md` §3 の 2026-09-04 行・証跡 `DD-037/manual-gate-t1-t2-observations.json`）。実 MS-IME の変換中に「あ」→候補 `['あお','あか']`、「あお」→`['あお']` と前方一致で絞り込まれ、**highlight は常に -1**（設計どおりキーを持たない）、確定も壊れないことを実機で確認した。変換候補ウィンドウと listbox の重なり・ちらつきも観測範囲では問題なし。当時の設計上の根拠（変換中も候補リストは**表示のみでキーを持たない**＝`decideSelectKey` は composing / 非 Navigation で必ず `'none'` を返し、picker のような入力所有権を持たない）が、実機でもそのとおり成立していることを確認した形になる。
- **編集中（suggest 表示中）の ↑↓ による候補選択は提供しない**（AC3 の一部）。状態機械が編集中の矢印を「キャレット移動」と定義しているため奪わない。代替は候補クリック、またはいったん Esc → Alt+↓ で picker を開く経路。要求が出たら「編集中に候補リストが開いている間だけ ↑↓ を奪う」拡張点として再検討する（折り返し列の複数行キャレット移動との両立が論点）。
- **`allowFreeText: true` で「候補を出さない」設定は提供しない**（従来の挙動に戻す逃げ道がない）。要求が出たら registry の `showsSuggestions` だけが分岐点になる（`GridSelectColumnType` に opt-out フラグを足す）。
- **候補の動的供給（依存列で候補が変わる・非同期解決）は対象外**（DD-027-1 の拡張点メモのまま）。
- **サーバー側の値検証は対象外**（`allowFreeText` は client の編集 UI/検証であって権限・整合性の強制ではない）。
