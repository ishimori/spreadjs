## 目的

**貼り付けた直後に、貼付範囲が選択された状態にする**（Excel 準拠）。利用者が「どこに何行×何列貼られたか」を画面で確認でき、そのまま Delete で取り消す・貼り直すといった後続操作につなげられるようにする。

## 背景・課題

- consumer（松下 生産納期の共同編集グリッド）のユーザー指摘: **「範囲選択してコピーし、起点セルで貼り付けても、どこに貼られたのか分からない」**（2026-09-03）
- 実測: `packages/grid/src/mount-controller.ts` の `performPaste`（L1871〜）は submit 成功時に `submitSetCells(op)` と `backend.view.markCellDirty()` を呼ぶだけで（L1906-1907）、**`selectionCtrl` に一切触れない**。単一セルを選んで 5行×3列を貼っても選択は 1×1 のまま = 貼付範囲を示すものが画面に無い
- 貼付位置の規則自体は正しい。`clipboard-controller.ts` の `buildPaste` は選択の左上（`range.rowStart` / `range.colStart`）をアンカーに matrix サイズ分を書き、1×1 → 複数セル選択では敷き詰める（tile）。**足りないのは結果の可視化だけ**
- consumer 側で代替できない: 利用側から選択レンジを設定する公開 API が無く、DD-035 R6 の `setActiveCell` は仕様上「明示レンジは解除」する（単一セルへ縮退）
- **Excel の実挙動**: ペースト後に点滅する破線（マーチングアンツ）は**コピー元**に付き、貼り付け先は「**貼付範囲が選択状態・アクティブセルは左上**」になる。したがって求めるのは一時的な点灯演出ではなく**選択レンジ化**。フラッシュ演出は描画予算とタイマーの話になるため本DDに含めない
- 先例: 範囲クリア（Delete）は「レンジを維持する」と決めている（DD-020-1 AC5: Delete は解除トリガーではない）。貼り付け後に選択が意味を持つのは同じ設計思想の延長
- 対象外（松下 §P の P2 / P3・優先度低・本DDでは扱わない）: 貼り付け確定の通知イベント（consumer のトースト用。松下側は 2026-09-03 に「トーストは作らない」を確定済み＝当面不要）／`GridConflict` への拒否詳細（rows/cols）の追加

### (b) が不成立である理由（Phase 1 の実読で判明・起票時の所見を否定）

`selection-controller` には**不変条件**がある（[selection-controller.ts:10-12](../../packages/grid/src/selection-controller.ts#L10-L12)）:

> 明示レンジは「anchor === activeCell（値一致）かつ phase === 'Navigation'」の間だけ存在する

そして editor の `onChange` が毎回 `syncWithEditor` を呼び、破れていればレンジを解除する（[mount-controller.ts:2483](../../packages/grid/src/mount-controller.ts#L2483)・DD-020-1 AC4）。

貼付アンカーは `range.rowStart` / `colStart`＝**矩形の左上**だが、activeCell は左上とは限らない。**右下から左上へドラッグして選択した場合、選択 anchor = activeCell = 右下、貼付アンカー = 左上** になる（`rangeFromAnchorFocus` が正規化するのは矩形であって anchor ではない）。

この状態で activeCell を動かさずに `extendTo(左上, 右下)` を呼ぶと anchor ≠ activeCell となり、**次の editor イベント（クリック・キー入力）で選択が予告なく解除される**。しかも `performPaste` は前段消費のため直後の `onChange` が走らない（[mount-controller.ts:2042](../../packages/grid/src/mount-controller.ts#L2042) の既知事情）ので、「貼った直後は見えるのに、次に何か触ると消える」という最も診断しにくい壊れ方になる。したがって (a) は好みではなく**要件**。

### 実装方針（Phase 2 の当たり・📐 で最終確定）

1. `buildPaste` の `PasteOutcome.submit` に**貼付矩形**を載せる（`anchorRow` / `anchorCol` / `targetRows` / `targetCols`。純関数のまま・DOM 非依存を崩さない）。tile・jagged・敷き詰めの分岐は既に `buildPaste` 内で解決済みなので、既存のローカル変数をそのまま返すだけで足りる
2. `performPaste` の `case 'submit'` で `submitSetCells(op)` 成功後（`op === null`＝全件スキップは**除く**＝論点⑦）に、既存のクリック経路と同型で:
   - `editor.pointerdownCell(左上)`（activeCell を移す。`onChange` → `syncWithEditor` がここで一旦レンジを解除する）
   - `selectionCtrl.extendTo(左上, 右下)`（**必ず pointerdownCell の後**。順序を誤ると自分で解除する）
   - `右下 = { row: anchorRow + targetRows - 1, col: anchorCol + targetCols - 1 }`
3. 拒否（`too-large` / `out-of-bounds`）・`noop`・全件スキップの各経路は**一切触らない**

**境界クランプは不要**: `out-of-bounds` が貼付矩形を事前に全体拒否する（[clipboard-controller.ts:123](../../packages/grid/src/clipboard-controller.ts#L123)）ため、`submit` に到達した矩形は常に表示 Axis 内。`extendTo` に `SelectionBounds` を渡す必要はない。

**1×1 貼り付けは自動的に AC3 を満たす**: `setRange` が同一セルを単一選択（`null`）へ正規化する（[selection-controller.ts:89-97](../../packages/grid/src/selection-controller.ts#L89-L97)）ため、特別扱いのコードを書かない。
