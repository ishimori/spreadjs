## 目的

アプリが行・列の境界に色と太さを指定した罫線を引き、横長の業務表で「同じ月の列」「同じ製品の行」「集計結果」を読み分けられるようにする。

起票後、SDK側で開始・完走・Release tarball作成のユーザー指示を受領。本DDで設計・実装・検証・配布物作成まで完了する。松下アプリへの適用は、[引き渡し資料](DD-047/handoff.md)と成果物を受けて別途行う。

## 背景・課題

### consumerの具体的な用途

| 画面 | 現状の読みづらさ | 必要な区切り |
|------|----------------|--------------|
| 製品別台帳② | 月ごとの「日付＋数量」の2列が横に連続し、隣月との境界が薄い | 各月の数量列の右に縦線。日付列と数量列の間は既定の細線を維持 |
| 製品別台帳② | 日別注文と注文合計・加工数・月末在庫が、同じ細線の表内に並ぶ | 注文合計エリアの開始、月末在庫の上下などに横線。既存の在庫行の背景色とも併用 |
| 納入計画③ | 得意先・製品名はブロック先頭にだけあり、スクロールすると行のまとまりを追いにくい | 製品・空箱ブロックの開始/終了を横線で区切る。日付と月計が並ぶ月境界にも縦線 |

全セルを一律に濃くすることではなく、業務上の境界を強調することが目的。どのRowId/ColumnIdを区切るかはconsumerが既存メタ情報から渡し、SDKへ「月」「在庫」等の業務概念を持ち込まない。

参照元は `C:/repo/matsushita-production-management` の `src/client/pages/ProductLedger.tsx` / `DeliveryPlan.tsx`、および `doc/archived/DD/DD-023/`。起票時の画面は同フォルダの `ledger-after.png` / `plan-after-target.png`。②の列IDは `d_YYYY-MM` / `q_YYYY-MM`、行IDは `r{Excel行}`。③は `d_YYYY-MM-DD` / `m_YYYY-MM` とDB由来の行IDを使う。

### SDKの現状（2026-09-05・alpha.3）

- `packages/render/src/base-layer.ts` の `drawPaneGrid` は一律の格子線を描く。既定色は `#d4d4d4`、幅は `deviceLineWidth(dpr)`。描画層内部の色指定はあるが、grid/reactの公開オプションには罫線指定がない。
- `packages/grid/src/index.ts` の `GridCommonMountOptions` と `packages/react/src/index.ts` は `columnBackgrounds` / `rowBackgrounds` を公開済み。背景色では月境界の縦線や集計行の上下線を表現できない。
- `columnFormats` は値の完全一致による背景色・文字色・バッジで、行列境界の指定機能ではない。
- `doc/plan/stage2-backlog.md` のセル単位書式には罫線も含まれる。本DDでは、既存の静的行列背景と同様の表示設定に用途を絞る案を採る。書式の共同編集・永続化が必要になれば、そのバックログへ分けて扱う。

## 検討内容

以下は起票時の検討材料。Phase 1で[公開契約](DD-047/contract.md)へ確定し、実装・試験した。

| # | 論点 | 起票時の案・確認事項 |
|---|------|--------------------|
| ① | APIの粒度 | 行の上/下、列の左/右を指定する静的な行列罫線。任意のセル範囲の囲み罫線は今回は要求しない |
| ② | 色・太さ・線種 | CSS色と幅を指定できる実線を最小範囲とする。1px/2pxをconsumer例とし、幅の単位・許容範囲・DPRへの合わせ方を契約化する。破線・二重線は将来候補 |
| ③ | 同じ境界への二重指定 | 隣接する行のbottom/top、列のright/leftは1本に解決する。太い線優先、同幅なら下側行のtop/右側列のleft優先を候補とする。キー挿入順には依存させない |
| ④ | 横線と縦線の交点・描画順 | 同幅の交点は横線優先を候補とする。行列背景・値ベース背景で線を消さず、選択枠/Presenceの視認性を保つ。最終的な優先順位を明文化する |
| ⑤ | 文字のはみ出し | 強調する縦境界で文字overflowを止める案。折返し・左外からの文字流入・ヘッダーの省略表示との整合を確認し、線が文字を横切る/文字で線が消える状態を避ける |
| ⑥ | IDと行操作 | RowId/ColumnId指定。行挿入・削除後も同じ行実体へ追従。新しい行へ指定を自動コピーしない。未知RowIdはDD-045同様の遅延解決/warnを候補とする |
| ⑦ | 範囲・固定領域 | データの空セルを含めて描く。固定paneをまたいでも連続させる。列境界線を列ヘッダーへ延長するか、行境界線を行番号へ延長するかも決める |
| ⑧ | React・モード・設定不正 | standalone/collaborationで共通。mount時固定・Reactは同値設定でremountしない案。未知列・無効な幅・空色・CSS不正色で前の線のスタイルを使い回さない挙動/診断を定義する |

### 公開API（alpha.4で提供）

```ts
interface GridBorder {
  readonly color: string;
  readonly width: number; // CSS px。有限の0超〜8以下
}
interface GridCommonMountOptions {
  readonly rowBorders?: Readonly<Record<string, {
    readonly top?: GridBorder;
    readonly bottom?: GridBorder;
  }>>;
  readonly columnBorders?: Readonly<Record<string, {
    readonly left?: GridBorder;
    readonly right?: GridBorder;
  }>>;
}
// 製品別台帳②相当。実際の行番号はconsumerの行区分メタから決める。
const options = {
  columnBorders: { 'q_2026-09': { right: { color: '#94a3b8', width: 2 } } },
  rowBorders: {
    r26: { top: { color: '#94a3b8', width: 2 } },
    r30: { top: { color: '#64748b', width: 2 }, bottom: { color: '#64748b', width: 2 } },
  },
};
```

React Facadeにも同名propを公開済み。既定格子線を残し、指定した境界だけを強調する。
