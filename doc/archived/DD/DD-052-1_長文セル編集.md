## 目的

ReadyCrew RC1（Alt+Enter＝セル内改行）・RC2（長文の編集欄）を実装する。既存 consumer（松下・広島）の Alt+Enter の挙動変化を CHANGELOG の破壊的変更節に記載する。

## 背景・課題

- 要件・現状: 親 DD-052 の RC1・RC2 行（`packages/ime/src/editor-state-machine.ts:281-289` が `altKey` を見ず確定＋移動、`packages/grid/src/integration-editor.ts:125-145,197-202` が textarea `rows=1`・セル矩形と同寸固定）
- 改行が行として描画されるのは `wrapColumns` の列だけ（`packages/render/src/text-cache.ts:14-15`）
- 親 DD-052 決定事項（本DDはこれを実装するのみ・再確認しない）:
  - 論点2 (a): Alt+Enter＝セル内改行。Enter は従来どおり確定＋下移動
  - 論点3 (b): `wrapColumns` の列だけに効かせる。それ以外の列では Alt+Enter も従来どおり確定＋下移動
  - 論点4 (a): 編集中の textarea を内容に合わせて下へ伸ばす（上限＋内部スクロール）。常駐 textarea 1本の IME 経路を維持

## 検討内容

設計判断（キー割当・対象列・エディター形状）は親 DD-052 の Human Spec Gate（論点2〜4）で確定済み。本DDで残る実装判断（textarea の伸長上限値・内部スクロールの発火閾値など）は Phase 1 の実読で確定する。

## 決定事項

- Alt+Enter は `wrapColumns` に含まれる列でのみ、キャレット位置へ改行文字を挿入し編集を継続する（確定・移動しない）
- `wrapColumns` に含まれない列では Alt+Enter も Enter と同じ確定＋下移動のまま変えない
- 編集中の textarea は内容の行数に応じて高さを自動調整し、上限（Phase 1 で具体値を決定）に達したら内部スクロールに切り替える。セルの列幅は変えない

- 実 Microsoft IME での変換中／変換確定直後の Enter・Alt+Enter の组み合わせは実機確認していない（Manual Gate M1 未実施）。既存の IME 状態機械の composing ガードは無変更（Alt+Enter の新分岐は `isEditingPhase`/`EditingAwaitFinalInput` の非 composing 経路のみに追加）のため、composing 中の既存 IME 保証（DD-002/DD-012 実機確認済み）への影響は無い設計だが、Alt+Enter 特有の組み合わせは未確認
