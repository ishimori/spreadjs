## 目的

Excel の `#,##0_);[Red](#,##0)` のように、**負の数を括弧付き・赤字で表示**できるようにする。日本の会計帳票で使う「▲1,234」も同じ枠で扱う。
表示だけの整形で、cell-commit・コピー TSV・columnFormats の判定に使う値（raw）は変えない（DD-033-2 の契約を維持）。

## 背景・課題

- OFIC（管理会計の Excel 刷新・2026-11-09 商談デモ）の入力画面を `@nanairo-sheet/react` で作る。先方の現行 Excel は入力欄の数値に
  `#,##0_);[Red](#,##0)` を使っている（部所用入力帳票の数値入力シートで 1,350 セル、中核ブックの実績入力で 1,143 セル。
  OFIC `doc/analysis/03_input-forms.md`）。損益（総利益・営業利益）や費用部門の値は負になることが多く、赤字・括弧での表示が業務の読み方になっている
- 現行の `columnDisplayFormats`（DD-033-2）は 3桁区切り・小数桁・%・前後の文字だけで、`display-format.ts` の拡張点メモに
  「負数の色/括弧表現」は v1 対象外と書かれている。`columnFormats`（DD-027-3）の文字色は表示文字列の完全一致でしか当てられず、「負なら赤」を表せない
- consumer 側で回避すると、表示用の文字列を値として持つことになり、cell-commit・コピーの値が崩れる

## 検討内容

### 論点1: I/F の形

| 案 | 内容 | 評価 |
|---|---|---|
| a（推奨） | `GridNumberDisplayFormat` に `negative?: { style?: 'minus' \| 'parentheses' \| 'triangle'; color?: string }` を足す | 書式と色が同じ設定にまとまる。Excel の書式（`;` の負セクション）と対応が付けやすい |
| b | `columnFormats` の match を数値条件（`{ lt: 0 }` 等）へ拡張して色を付け、括弧は display format 側 | 色と形が別設定に分かれる。数値条件の match は別の需要（範囲で色分け）にも効くが、本件には過剰 |

### 論点2: 色の描画経路

`base-layer` の `formatCellText(col, raw) => string` は文字列しか返せない。案 a では「raw → { text, textColor? }」の写像にするか、
数値列の負判定を base-layer に足す必要がある。columnFormats の `textColor` との優先順位（書式ルールが優先か）を決める。

### 論点3: 正の数の右余白

Excel の `_)` は正の数の右に括弧1文字分の余白を取り、正負で桁がそろう。v1 で入れるか（入れないと正負で1文字ずれる）。

## 決定事項

2026-10-22 の Human Spec Gate でユーザーが推奨案を選んだ。細目（★）は推奨案の説明に含めて提示した内容。

1. **I/F（論点1=案a）**: `GridNumberDisplayFormat` に `negative?: { style?: 'minus' | 'parentheses' | 'triangle'; color?: string }` を足す（Experimental 0.x の追加のみ）
   - `'minus'`（既定）= `-1,235`（従来どおり）／`'triangle'` = `▲1,235`／`'parentheses'` = `(1,235)`。`color` だけの指定（`-1,235` を赤）も可
   - ★ ▲ は `-` と同じ位置（prefix の後: `¥▲1,235`）。括弧は prefix〜suffix の全体を囲む（`(¥1,235)`・`(12.3%)`）
   - ★ 0 に丸まる負数（-0.04 → `0.0`）は負として扱わない（括弧・▲・色を付けない。DD-033-2 の -0 正規化を維持）
2. **色の優先順位（論点2）**: columnFormats の `textColor`（値の完全一致） ＞ 負の数の `color` ＞ 既定の数値色。バッジの文字色も同じ順位
   - 色は base-layer に新しい描画フック（列 index・raw → 文字色・右余白）で渡す。判定は raw・描画は display（DD-033-2 の契約を維持）
   - `color` の CSS としての妥当性は検査しない（columnFormats・columnBackgrounds と同方針）。描画は既定色を入れてから上書きし、不正な色は既定色で描く（直前のセルの色を引き継がない。DD-036 と同じ理由）
3. **正の数の右余白（論点3）**: `'parentheses'` の列では、正の数と 0 の右に `)` 1文字分の余白を自動で取る（Excel の `_)`）。設定項目は増やさない
   - 余白の幅は描画時にセルのフォントで `)` を測る。列境界ダブルクリックの自動列幅も余白込みで測る。バッジ・数値以外の raw には付けない
4. **配布**: 本DDでは alpha を切らない。DD-060（セル入力の検証）の完了時に同じ alpha で OFIC へ配布する

## 既知の未保証境界

- 0 に丸まる負数（decimals 0 の -0.4 → `0`）には括弧・色を付けない。Excel は丸める前の符号で書式を選ぶため `(0)` の赤字になる（決定事項1★で SDK の -0 正規化を優先した）
- `color` の CSS としての妥当性は検査しない。不正な色は既定の数値色で描く
- OFIC の画面での見え方は、DD-060 の alpha を OFIC が取り込んだ後に OFIC 側で確かめる（本DDでは配布しない・決定事項4）
- 白三角（△）の表記は対象外（`display-format.ts` の拡張点メモ）
