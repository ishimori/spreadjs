## 目的

DD-060 のセルの状態表示を、共同編集モードでも使えるようにする。

## 背景・課題

- DD-060 は状態を単独モードの行データ（`setRows`／`setData` の `cellStatus`）だけで付けられるようにした。共同編集モードでは `setRows`／`setData` 自体が無視されるため使えない（DD-060 の既知の未保証境界）
- 共同編集モードの consumer（広島空港 PoC 等）でも、確定後の検証結果やサーバー側の検証結果をセルに出したい場面がある

## 決定事項

ユーザー委任（2026-10-22）により推奨案で確定した。

1. **両モード共通のメソッド `setCellStatus(rows)`** を `GridInstance` と React の ref handle に足す。`rows` は `{ rowId; cellStatus: Record<ColumnId, GridCellStatus> }` の配列（公開型 `GridCellStatusRow`）。渡した行の状態を丸ごと置き換え、`{}` で消す（DD-060 の `setRows` の `cellStatus` と同じ決まり）
2. **状態は各クライアントの画面だけに持つ**（view-local）。サーバーへ送らず、他の参加者には共有しない（検証結果はクライアントごとに consumer が付ける）。永続化・Undo・cell-commit の対象外（DD-060 と同じ）
3. **単独モードでも使える**。`setRows`／`setData`／`initialData` の `cellStatus` と同じ置き場所を共有する（`setData` は文書の丸ごと差し替えなので、`setCellStatus` で付けた状態も含めて作り直す）
4. **mount 直後（boot 前）に呼んでもよい**。状態は backend と独立に持ち、描画が始まれば反映される
5. 未知の RowId（まだ届いていない行・削除済みの行）も受け付ける（行が現れれば描かれる。削除済みの行は描かれない）。未知の列は描かない。不正な `level` と Record でない `cellStatus` は DD-060 と同じく無視して `cell-status-invalid` で通知する
6. `cell-hover` の `status` と状態変化時の出し直しは両モードで効く

## 既知の未保証境界

- 状態は他の参加者と共有しない（決定事項2）。共有したい場合は consumer が各クライアントで同じ検証をして付ける
- 削除された行・まだ届いていない行の状態も置き場に残る（描画には出ない。単独モードの setData で消える）
- 共同編集モードで行が後から届いたときに描かれることは、E2E では確かめていない（置き場は未知の RowId を受け付け、描画は毎フレーム RowId を解決する作りで担保）
