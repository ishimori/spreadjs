## 目的

wt%・比率・ppb・単価などの列で、数値にならない入力（「<0.1」「ND」「－」「12.5%」など）を確定させない。数値かどうかの判定は SDK の型変換（全角数字・桁区切り）と揃える。

## 背景・課題

- consumer の依頼 #5。今は `validateCell` で consumer が書けば代用できるが、「数値の列は数値だけ通す」はどの案件でも同じ決まり（ユーザー判断 2026-11-20）。consumer ごとに判定を書くと、SDK の型変換（全角の `１２３`・桁区切りの `1,234` を数値にする）と食い違いうる

## 決定事項

- 2026-11-20（親 DD-070・推奨案で確定）:
  1. `columnTypes: { wt: { type: 'number' } }`（公開型 `GridNumberColumnType`）。任意の `invalidMessage`（拒否したときの `cell-invalid` の `message`。既定は「数値を入力してください」）
  2. 判定: 確定しようとしている値が空でなく、SDK の型変換（`parseCellInput`）の結果が数値でなければ拒否。全角数字・全角マイナス・3 桁区切りは数値として通す（型変換と同じ）。日付の形（`2026-01-02`）・`12.5%`・`<0.1`・`ND`・`－` は拒否
  3. 拒否の経路は `validateCell`（DD-063）と同じ: 入力を捨てて `cell-invalid` で知らせる（貼り付け・Ctrl+D／Ctrl+R は 1 件でも不正なら全体を拒否し、不正なセルを全部載せる）。検証する経路は IME/textarea の確定・貼り付け・Ctrl+D／Ctrl+R。検証しない経路も DD-063 と同じ（空にする確定・Undo/Redo・`setRows`/`setData`・リモートの変更）
  4. 数値の列で数値として通ったセルは、そのあと consumer の `validateCell` にも渡す（範囲の検査などは consumer）。数値でなかったセルは `validateCell` を呼ばない
  5. 併用: `stringColumns` と同じ列は mount 時に fail-fast（`column-types-invalid`。数値にしない列と数値だけの列は両立しない）。`columnDisplayFormats` の number 書式・`readOnlyColumns`・`wrapColumns` とは併用できる
  6. 両モード共通。文書・Operation・snapshot は変えない（数値は今も型変換で数値として持つ）

## 既知の未保証境界

- 数値の列でも日本語入力（IME）は自動で切り替えない（ブラウザーから IME のオン・オフを決められないため。全角数字で打てば数値として通る）
- `setData`・`setRows`・リモートの変更で入った数値でない値は拒否しない（データを捨てない・DD-063 と同じ）。表示はそのまま
- 共同編集モードの E2E は足していない（検証の関所は両モード共通・DD-063 の共同編集の E2E が同じ関所を通る）
